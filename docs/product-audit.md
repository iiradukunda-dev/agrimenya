# Agri-Menya product and engineering audit

Reviewed: 2026-10-23. This inventory describes the repository implementation; availability in a deployed environment still depends on its database, environment variables, and external providers.

## Architecture and entry points

- The browser application is a multipage Streamlit app. `frontend/Home.py` is the home entry point; `frontend/pages/` contains the page wrappers; `frontend/views/` holds the workflows; `frontend/components/` and `frontend/utils/` provide shared rendering and API access.
- `backend/app/main.py` creates FastAPI, mounts feature routers, configures security headers and health/readiness checks, and uses Supabase through `backend/app/db/crud.py`.
- The UI calls the API through `frontend/utils/api_client.py`, except the authenticated community UI, which makes explicit requests to its community routes.
- The implementation remains Streamlit + FastAPI + Supabase. This audit did not replace the architecture or infer missing functionality from the visual design alone.

## Verified data and security paths

- `backend/app/routers/decision.py` calls `predict_with_interval`, creates the structured response, and persists it. `backend/app/ml/predict.py` uses available database yield evidence and the bundled NISR SAS file; a serialized model is only activated with a matching model card, feature schema, and artifact hash. Current health explicitly reports no active model.
- `backend/app/routers/admin.py` validates the normalized NISR CSV and stages a release; the NISR records are distinct from farmer field reports.
- `frontend/components/maps.py` loads local district boundaries, draws zone points and district summaries, and exposes the RSA imagery layer only as visual context.
- Community routes use individually signed community sessions for private feed/write operations. Admin routes use named admin sessions and check account state/session version. Development-mode user endpoints are intentionally more permissive than production; production settings must be configured before deployment.
- Streamlit stores community and administrator bearer tokens in server-side session state; the app does not issue a browser authentication cookie. Community and administrator tokens expire after one hour and 30 minutes respectively, and APIs enforce JWT expiration. A browser refresh or lost Streamlit WebSocket session can require sign-in again. Persistent browser sessions need a same-origin backend-for-frontend that issues `HttpOnly`, `Secure`, `SameSite` cookies and protects cookie-authenticated writes against CSRF; do not persist bearer tokens in JavaScript-readable cookies or local storage.
- Farmer image uploads are bounded, decoded/validated, compressed by the frontend, and stored privately; the API returns short-lived signed URLs. Public post/report responses do not need to expose account email addresses.

## Changes made in this pass

- Replaced the cycling language icon with an explicit EN/RW selector.
- Reorganized the existing feature finder into Workspace, Intelligence, Community, Administration, and About groups; administrator entry remains visible for sign-in, while protected actions remain API-authorized.
- Organized Home around searchable destinations and task cards for zones, segmentation, decisions, planning, AI, communication, community, administration, and feedback.
- Changed the assistant and community sign-in/register workflow from tabs to conditional controls. Streamlit tabs execute all their contents on each rerun; inactive forms could trigger unnecessary API work. The community view now uses the shared language selector instead of a second competing one.
- Changed the zone records panel to load only the selected field-observation, readiness, or worker-day workflow.
- Passed the previous bounded conversation turns to the chat API, which already accepts history, and constrained each prompt to the backend's 500-character limit.
- Changed field-observation location selection to identify a specific saved zone. Previously a district-to-zone dictionary silently selected one arbitrary zone when the district contained multiple zones.
- Matched the community username input length to the backend's 3–30 character constraint.
- Added explicit confirmation before administrator moderation permanently deletes a post or a farmer observation.
- Reworked the community composer so the update is primary and its title is optional; it is derived from the update for the existing API contract. Kept discussion and field-observation views conditional to avoid unnecessary inactive-tab requests.
- Added a public WhatsApp chat entry point that appears only when a live sender number is configured; clarified command and alert-consent behavior. Added confirmation before admin contact deactivation or alert dispatch.
- Tightened the contact form's required-field/email checks and clarified when a submission fails.
- Made Community clear expired bearer sessions and prompt the user to sign in again; documented the current non-persistent Streamlit session model and secure cookie-session requirements.
- Added a Settings page for language/time-zone visibility, session status and sign-out, and clearing the transient AI conversation; linked it from Home without exposing deployment secrets.

## Remaining gaps to address before claiming a complete production system

1. Finish Kinyarwanda translations outside the community workflow; several analytical and administrative pages are English-only.
2. Add authenticated role-specific navigation only after the application has a real account/session model for non-community users. Today, admin is a protected workspace and user API access is configured by deployment key, not a general farmer/planner identity system.
3. Provide an audited model deployment only if an evaluation on representative, correctly aligned NISR data supports it. Do not label the baseline as ML.
4. Add citation/source detail to the assistant response contract if users need clickable evidence; the current contract exposes only a source label.
5. Build a dedicated field-activity status/history data model if plans need saved completion, overdue, or change-history workflows. Current roadmaps are plan steps, not a full task-management lifecycle.
6. Verify production database migrations, storage bucket setup, API keys, allowed hosts/origins, outbound mail, and Meta credentials in the actual deployment. Repository presence alone cannot verify remote configuration.
7. Use a shared rate-limit store for multi-worker production deployments where abuse controls must be consistent across processes.
8. If users need authentication to survive browser refreshes or deployments, implement a same-origin cookie session proxy and CSRF protections; current Streamlit sessions are intentionally non-persistent.

## Design and engineering principles retained

- Official NISR records, database observations, model outputs, community reports, forecasts, and general guidance must retain distinct labels.
- Missing values remain unavailable rather than becoming zero. Historical fallback periods and source labels should stay visible.
- District maps and point data must not imply field boundaries or farm-level certainty.
- Restrict work to supported backend fields and preserve backend authorization as the security boundary.
